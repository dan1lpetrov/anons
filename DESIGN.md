# Design Guidelines — Anons

Вставити цей файл у проект (наприклад `DESIGN.md` поруч з `CLAUDE.md`) і посилатись на нього в промптах: "дотримуйся DESIGN.md при створенні/зміні UI". Файл містить дві незалежні системи: **Admin Panel** (для власника) і **Storefront** (для покупця, здебільшого через Telegram mini app).

---

# 1. Admin Panel

## Напрямок

Мінімалістична, "повітряна" світла тема + дзеркальна темна (auto по системній темі, з можливістю перемкнути вручну). Референс: чисті SaaS-дашборди з картками-KPI, тонкими бордерами замість важких тіней, спокійною типографікою. Без зайвої декоративності — це робочий інструмент, яким людина користується щодня по кілька годин.

## Кольори

Задавай через CSS-змінні, обидві теми повністю симетричні.

**Light**
- `--bg`: `#FAFAFA` — фон сторінки
- `--surface`: `#FFFFFF` — картки, таблиці, модалки
- `--border`: `#E5E5E5` — тонкі роздільники, 1px
- `--text-primary`: `#171717`
- `--text-secondary`: `#737373`
- `--accent`: `#2563EB` — основна дія (кнопки, лінки, активний стан)
- `--success`: `#16A34A` — товар в наявності, замовлення виконано
- `--warning`: `#D97706` — мало на складі, очікує обробки
- `--danger`: `#DC2626` — немає в наявності, скасовано

**Dark**
- `--bg`: `#0A0A0A`
- `--surface`: `#151515`
- `--border`: `#262626`
- `--text-primary`: `#FAFAFA`
- `--text-secondary`: `#A3A3A3`
- `--accent`: `#3B82F6`
- `--success`: `#22C55E`
- `--warning`: `#F59E0B`
- `--danger`: `#EF4444`

Ніяких додаткових "фірмових" кольорів типу бренд-фіолетового чи градієнтів на кнопках — акцент один, `--accent`, і статусні кольори. Все інше — відтінки сірого.

## Типографіка

- Шрифт: `Inter` або `Geist` для всього — і заголовків, і тексту, і чисел. Без другого декоративного шрифту, це не маркетинговий лендінг.
- Числа (ціни, кількості, суми в таблицях) — з `font-variant-numeric: tabular-nums`, щоб колонки не "стрибали".
- Шкала: `12px` (лейбли, підписи) → `14px` (основний текст, таблиці) → `16px` (заголовки карток) → `20-24px` (заголовок сторінки). Без різких стрибків.
- Вага: `400` — основний текст, `500` — лейбли/заголовки карток, `600` — тільки заголовок сторінки і критичні цифри (сума замовлення).

## Layout

```
┌─────────┬──────────────────────────────┐
│         │  Заголовок сторінки   [Дія]   │
│  Sidebar├──────────────────────────────┤
│  (nav)  │  KPI-картки (3-4 в ряд)       │
│         ├──────────────────────────────┤
│         │  Таблиця / контент            │
│         │  (фільтри зверху, пагінація   │
│         │   знизу)                      │
└─────────┴──────────────────────────────┘
```

- Sidebar: іконка + текст, активний пункт — не заливка кольором, а тонка вертикальна риска зліва + `--accent` на іконці/тексті.
- Картки: `--surface` + `1px solid --border`, **без box-shadow** або дуже легка (`0 1px 2px rgba(0,0,0,0.04)`). Border-radius 8-10px, не 20+.
- Таблиці замовлень/товарів: рядок висотою ~48px, hover — легка зміна `--bg`, без зебри (rows striping). Статус — маленький бейдж (rounded pill) кольором статусу, не вся строка.
- Форми (додавання товару, налаштування акції): лейбл зверху інпуту, не збоку. Групуй пов'язані поля в картки з підзаголовком секції.

## Компоненти

- Кнопки: primary — заливка `--accent`, білий текст, radius 6-8px, без градієнтів і теней. Secondary — тільки border, прозорий фон.
- Інпути: border `--border`, фокус — border стає `--accent` + легкий outline-ring, без "неонового" glow.
- Модалки/side-panel для форм (додати товар, створити акцію) — не окрема сторінка, щоб не втрачати контекст списку.
- Порожні стани (немає замовлень/товарів): іконка-аутлайн + одне речення що робити далі + кнопка дії. Без мультяшних ілюстрацій.

## Чого уникати

- Фіолетово-рожевих градієнтів і "AI-стартап" вайбу
- Важких тіней і skeuomorphism
- Емодзі в інтерфейсі замість іконок (іконки — `lucide-react`)
- Різних border-radius на сусідніх елементах (обери 1-2 значення і тримайся їх усюди: напр. 8px для карток/кнопок, 6px для інпутів/бейджів)
- Кольорового шуму: якщо є вибір показати статус кольором чи текстом+іконкою — думай, чи потрібен колір взагалі

# 2. Storefront (сайт для покупця, Telegram mini app + десктоп)

## Контекст

Не бренд-магазин, а **агрегатор знижок**: товари з різних сторонніх сайтів, зібрані в один каталог, з можливістю оформити замовлення. Головний user flow — швидкий візуальний скрол товарів у Telegram на мобільному, десктоп — вторинний, має просто коректно працювати (не обов'язково окремий "розкішний" desktop-досвід).

Напрямок: mobile-first fashion-app стиль — заокруглені картки товару, м'які тіні, чіпи категорій, яскраві бейджі знижки. Тепліше й "живіше" за адмінку — це має відчуватись як шопінг-апка, а не робочий інструмент.

## Кольори (адаптивна тема)

**Light**
- `--bg`: `#FFFFFF`
- `--surface`: `#FAFAFA` — картки товару
- `--border`: `#EFEFEF`
- `--text-primary`: `#171717`
- `--text-secondary`: `#8A8A8A`
- `--accent`: `#FF5A5F` — CTA-кнопки ("Замовити", активні чіпи), теплий коралово-червоний — асоціюється з розпродажем, але не кричущий
- `--discount-badge`: `#FF5A5F` на білому тексті
- `--price-new`: `--text-primary`, жирний
- `--price-old`: `#B5B5B5`, закреслений
- `--success`: `#16A34A` — "в наявності", підтвердження замовлення

**Dark**
- `--bg`: `#0E0E0E`
- `--surface`: `#1A1A1A`
- `--border`: `#2A2A2A`
- `--text-primary`: `#FAFAFA`
- `--text-secondary`: `#9A9A9A`
- `--accent`: `#FF6B70`
- `--discount-badge`: `#FF6B70`
- `--price-old`: `#6B6B6B`
- `--success`: `#22C55E`

Один яскравий акцент на весь інтерфейс (коралово-червоний) — не розкидай кольори по іконках/декору, тримай його тільки для CTA й знижок, щоб він не втрачав силу.

## Типографіка

Той самий шрифт, що і в адмінці (Inter/Geist) — для консистентності бренду між частинами продукту. Але тут ціна — головний акцент на картці:
- Назва товару: `14px / 400`, максимум 2 рядки, обрізка з `...`
- Нова ціна: `16-18px / 700`
- Префікс "від" (коли в товару є діапазон цін по кольорах) — окремий `<span>` меншим шрифтом (`11px / 500`, `--tg-hint`), а не той самий розмір/вага що й число — і число+`₴` завжди зі скрапленим (nbsp) пробілом між ними, щоб браузер не переносив символ валюти на новий рядок окремо від суми
- Стара ціна: `13px / 400`, закреслена, `--price-old`
- Бейдж знижки: `12px / 600`, білий текст на `--discount-badge`, pill-форма

## Головний екран (Home)

Головна — це вітрина, а не каталог: банер(и), топ товарів, категорії. Повний список з фільтрами живе окремо на екрані "Каталог" (`CategoryFilter` + `CatalogControls` + сітка), куди ведуть кнопка "Дивитись всі" й тайли категорій.

```
┌─────────────────────────┐
│  Anons              [🔍]│  ← топбар (кошик тут лише на десктопі)
├─────────────────────────┤
│ ┌─────────────────────┐ │
│ │      [банер]         │ │  ← карусель, full-bleed, скрол-снап
│ │  SS24 COMING SOON     │ │
│ └─────────  · ·  ───────┘ │
├─────────────────────────┤
│ Топові товари   Дивитись всі →│
│ [фото][фото][фото][фото]→ │  ← гориз. скрол, картки товару
├─────────────────────────┤
│ Категорії                │
│ ┌───────────┬──────────┐ │
│ │  [Взуття] │ [Одяг]   │ │  ← 2 колонки, фото + назва поверх
│ └───────────┴──────────┘ │
├─────────────────────────┤
│  🏠 Головна ▦ Каталог 🛒 Кошик 🧾 Замовлення │ ← нижня навігація, fixed
└─────────────────────────┘
```

- Банер: адмін-контент (окрема секція в `/admin`, картинка + заголовок/підзаголовок + опційне посилання на категорію). Якщо банерів немає — секція просто не рендериться, ніякого заглушкового контенту.
- "Топові товари" — не окрема ручна курація, а перші N товарів з уже наявного глобального ранжування (`product_scores`, той самий порядок що й у каталозі "За рекомендацією"). "Дивитись всі" веде в Каталог без фільтра категорії.
- Категорії — плитки, а не чіпи: фото представника категорії, темний градієнт-скрим знизу, назва поверх. Джерело — вже наявна `categoryId` таксономія товарів, без нових даних.
- Картка товару (і на Home, і в Каталозі): фото 3:4, `border-radius: 12-14px`, легка тінь (`0 2px 8px rgba(0,0,0,0.06)`), бейдж знижки — верхній правий кут фото, лейбл сайту-джерела (звідки товар) — маленький текст під фото. Фото — `object-fit: contain` на фоні `--border`, не `cover`: вихідні фото з різних брендів/скрейпів мають різну композицію (товар впритул vs. на моделі з відступами), і `cover` кадрує кожне по-своєму, через що товари в сусідніх картках виглядають на різному "рівні"/масштабі. `contain` завжди показує товар цілком, без обрізання, ціною невеликих полів навколо на деяких фото.
- Нижня навігація — fixed, 4 пункти (Головна / Каталог / Кошик / Замовлення), іконка + підпис, активний — колір `--accent`. На мобільному кошик живе тільки тут (не дублюється в хедері). "Замовлення" — легка історія покупок за Telegram-ідентифікацією (без пароля/реєстрації, це не повноцінний акаунт), не повноцінний кабінет користувача — статус показуємо тим самим бейджем-пігулкою кольором статусу (заповнений `--success` = зроблено, приглушений нейтральний = ще ні), без таблиць чи фільтрів.
- Чіпи категорій у Каталозі — `border-radius: full`, неактивні — `--surface` + border, активний — заливка `--accent`, білий текст.
- Кнопка "Замовити" на картці/сторінці товару — завжди `--accent`, повна ширина на мобільному.

## Layout — десктоп

Той самий каталог, просто ширша сітка (4-5 колонок замість 2), чіпи категорій можуть стати вертикальним фільтром зліва. Нижня навігація зникає, замінюється звичайним хедером з пошуком і кошиком. Ніякої окремої "десктопної" концепції — це той самий каталог, що масштабується.

## Терміновість — помірно

Дозволено:
- Бейдж відсотка знижки на кожній картці (завжди, це і є суть сервісу)
- Текстовий тег "залишилось мало" тільки коли дані про залишок реально відомі — не вигадувати штучний дефіцит
- Позначка "нова знижка" для щойно доданих товарів (наприклад бейдж `NEW` поруч зі знижкою)

Уникати:
- Countdown-таймерів "розпродаж закінчується через..."
- Спливаючих "N людей зараз дивляться цей товар"
- Будь-якого штучно згенерованого соціального доказу

## Джерело товару (важливо для довіри)

Оскільки товари агреговані з чужих сайтів — завжди показуй, звідки товар (назва магазину-джерела, маленький логотип якщо є), і на сторінці товару — явне посилання/кнопку "Перейти на сайт продавця" або пояснення як працює замовлення через Anons. Це не другорядна деталь, а частина довіри до сервісу.
